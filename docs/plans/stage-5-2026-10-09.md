_Written 2026-10-09 evening when Jakub told the coordinator to continue into Stage 5 without
further approval. Stage 5 is Track 7.4 in `ROADMAP.md`, in three steps (7.4a cross-server DMs
and the request inbox, 7.4b remote workspace members through the user's relay, 7.4c the public
relay), under the decisions in `docs/decisions/decentralization-2026-10-08.md` and

## What Stage 5 must deliver

- **A person is a key, not an account on a server.** Any rim-server can be someone's relay; the
  profile card names their relays; switching relays loses nothing (history is on the drive, keys
  on the devices, workspaces on their hosts).
- **The relay is an untrusted courier.** The app talks to one endpoint, its relay, over the same
  GraphQL and WebSocket it uses today. The relay delivers DMs between relays, holds the request
  inbox, profile cards and MLS key packages, and forwards workspace traffic to each workspace host
  the person belongs to, both ways, unchanged: writes carry the user's device signature, hosts
  sign their events, and the client verifies host events against the host key pinned from the
  invite. The host stays the only authority and sequencer for its workspace.
- **Servers talk over a small signed HTTP API**, not GraphQL: HTTP Message Signatures with
  replay protection and rotatable server keys, a non-GraphQL transport in the `file_handlers.rs`
  pattern. Hosts accept any relay by default, with an optional allow-list and limits per relay key
  and per delegation.
- **DMs and private groups stay ciphertext on relays** (Stage 4); plaintext channels are
  readable by a relay while queued, as they are by the host (accepted in the relay decision).
- **`relay.rim.chat`** runs as a stock rim-server in relay mode with a runbook and an abuse
  policy; registering a key there needs proof-of-work or an invite.
- A direct connection to a host is the fallback when the relay is unreachable.

## Rules for every PR

- Branch `feature/<slug>-<6 random chars>` off `master`; one PR per row; commit messages are
  plain imperative sentences with no trailers (no `Co-Authored-By`, no `Signed-off-by` until
  Jakub says otherwise).
- Implementers run every gate and paste the tails; the coordinating session reviews, fixes and
  merges (`CLAUDE.md`, "Code Review"). CI is over quota; the local gates are the gate.
- Comments say what a thing is and does; no history, no doc references.
- Crypto: no hand-rolled primitives; Ed25519 through `rim_identity`'s existing encodings; HTTP
  Message Signatures through a maintained crate if one fits, else a minimal, vector-tested
  implementation of the RFC 9421 profile the spec fixes.
- Migrations are additive; a single-server deployment keeps working with no configuration change
  (it is its own relay and host).
