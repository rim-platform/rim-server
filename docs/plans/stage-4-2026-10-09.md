# Stage 4: private DMs and groups (plan, 2026-10-09)

_Written 2026-10-09 when Jakub gave the go after Stage 3 closed (`stage-3-remaining-2026-10-09.md`).
Stage 4 is Track 7.3 in `ROADMAP.md`: end-to-end encryption with MLS for DMs and private groups,
on the Tauri side, with a hybrid X25519 + ML-KEM-768 key agreement
(`docs/decisions/post-quantum-hybrid-2026-10-09.md`). Channels stay plaintext. This file lists
the PRs in the order they ship and is the brief each implementer works from._

## What Stage 4 must deliver

A server operator with full database access cannot read a DM or a private group. Concretely:

- DMs and private groups are MLS groups whose members are **devices** (every device of every
  member, each with its Stage 3 device key as its MLS credential). The server stores and
  relays ciphertext, key packages, Welcome and Commit messages, and is the sequencer: it accepts
  one Commit per epoch so racing commits cannot fork a group.
- The client encrypts and decrypts, keeps plaintext only in its encrypted local cache and the
  person's own drive archive (Stage 2), and never backs up MLS group state: a new device joins
  each group fresh through a Welcome from an existing device and reads older history from the
  archive.
- Every server feature that reads message text gets a client replacement in encrypted
  conversations, or is switched off there: mentions still notify (the client sends mentioned
  principal ids beside the ciphertext), attachments are encrypted on the client, search is
  local, pipelines and the agent see metadata only, plugins read decrypted messages only through
  the client message service under a per-plugin grant (open decision 6: grant).
- Message franking for reports is designed at the start, so a reported message can be proven
  to a moderator without the server having read it.
- Existing conversations: new DMs and new private groups are encrypted; existing ones are
  upgraded by the client that can (an owner's device) through a one-time migration with a
  visible marker; messages from before the upgrade stay plaintext on the server.

## Rules for every PR

- Branch `feature/<slug>-<6 random chars>` off `master`; one PR per row; commit messages are
  plain imperative sentences with no trailers.
- Implementers run every gate and paste the tails; the coordinating session reviews, fixes
  and merges (`CLAUDE.md`, "Code Review"). CI is over quota; the local gates are the gate.
- Comments say what a thing is and does; no history, no doc references.
- Crypto: no hand-rolled primitives; OpenMLS and its provider behind one seam; every primitive
  tested against published vectors; nothing claimed secure without a test that would fail if it
  were not.
- An outside review of Stages 3 and 4 is still owed before a public release
  (`ROADMAP.md`, "Risks").
