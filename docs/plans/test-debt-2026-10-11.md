## Rule

Tests pin behaviour someone could break without noticing: permission boundaries, error
mapping, limits, the shape of a result. A test must fail when that behaviour changes. Tests
that only replay what the code happens to do today are not written; an agent that cannot test
a behaviour without a refactor reports it instead of forcing it. Coverage is the measure of
progress, not the goal.

Bugs found by the tests and fixed on the way: unreachable confirmation path and unbounded
recursion on a stored user-command cycle (#119); pipeline edits open to every member, and
malformed ids without an error code (#120); typing bypassing the timeout, guests seeing every
member's presence, orphaned emoji files (#121); user commands wrapping a Mutating step
skipping the agent gate (#122); macro create without a membership check and macro execute
open to any user (#117); dataloader errors without a code (#128); `forwardedFrom` resolving a private channel's message for any reader, and malformed audit log cursors and time bounds silently widening the page (#131).

Open after the plan: pipelines cannot write (actions run as the agentic Plugin initiator, so
every builtin write needs a confirmation a pipeline cannot give; pinned by
`a_pipeline_cannot_write_because_its_writes_need_a_confirmation` until Jakub decides the
policy); an injectable clock in `DefaultPipelineService` for the breaker's 60-second window;
the broadcaster exposed on the test node for the fired and suspended events; the `db-tests`
rollback tests drop and re-add columns on `message` every cycle and Postgres never reclaims a
dropped column's slot, so a long-lived test database hit the 1600-column limit on
2026-10-11; since #135 every db-tests process recreates its database first.

Bug fixes from Jakub's manual testing jump the queue at any point.

### Round two result

R-1 to R-3 found eight wrong answers (#132, #133, #134), so the stop rule did not fire; R-4
found one more (#136). Round two is closed. Pinned as current behaviour, for Jakub to decide:

- `commandDiscover` filters by capability, not role: members and guests see `admin.timeout`
  and `chat.set_slow_mode`, which the service refuses them; a workspace the caller is not in is
  not refused, it lists the commands that need no capability.
- A user outside the workspace answers three codes: `FORBIDDEN` from `createConversation`,
  `VALIDATION` from `addConversationMembers`, `NOT_FOUND` from the moderation roots.
- `updateUserCommand` and `deleteUserCommand` answer `NOT_FOUND` for an id outside `user.`,
  `createUserCommand` answers `VALIDATION`.
- `resetPassword` and `joinServerByInvite` answer `NOT_FOUND` / `FORBIDDEN` for a bad token; the
  signup roots answer `INVALID_TOKEN` / `EXPIRED_TOKEN`.
- A workspace-invite signup stores `<username>@local.invalid` and drops the typed email, so the
  account cannot reset its password.
- `sendMessage` accepts blank text (attachments follow); reply and edit refuse it. A page size
  below one reads one item. A member who has not joined a public channel may still set its topic
  and pin there. Only the author finalizes or deletes an attachment.
- A guest in a public channel sees the profile and reactor ids of a member who left the channel
  and still posts there.
- Another account presenting someone's valid identity statement answers `VALIDATION` for a
  certificate or card, `FORBIDDEN` for a rotation, `NOT_FOUND` for a revocation.
- A recovery rotation sent with another account's session answers `FORBIDDEN`; the same request
  with no session succeeds.

## Rules for every PR

A worktree off master, one feature per agent, one test database per agent,
`CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0`, every gate, plain imperative commits without
trailers, the coordinating session reviews and merges. Tests live where the logic lives: mocks
in `rim_infra_services` for service behaviour, the e2e suite for the GraphQL contract. Jakub's
three rules: no boilerplate; shared setup goes through fixtures so a test shows only what it
varies; before writing a test, search the existing suites for one that already pins the
behaviour and extend it rather than add a second. No
production code changes beyond what a test needs to reach a behaviour, and those are named in
the PR.
